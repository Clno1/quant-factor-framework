## 周一如何验收

已有消费者将从 9/14 北京时间 16:00 开始留档。默认检查点为美东
08:15、09:25、09:35，即北京时间 20:15、21:25、21:35。尚未到达的时点显示 WAITING，
没有伪造未来报告。当天晚些时候运行同一命令，仍可重建早上各时点的状态。

```bash
ssh root@43.156.89.232 '/home/projects/quant/.venv/bin/python /home/projects/quant/tools/ep-session-audit-20260912-v2/scripts/audit_ep_session.py --config /etc/quant/ep-event-worker.json --session 2026-09-14 --output /home/projects/quant/data/ep/session_acceptance/2026-09-14.json'
```

默认自动纳入当天 PRICE_WATCH 或已有原文匹配时钟的股票，不需要手工指定成功样本。
排查某只没出现的股票时添加 `--tickers ORCL,CPRT,RH`；查看指定截止时间可添加
`--as-of 2026-09-14T09:35:00-04:00`。参考表用 `--references` 指定，必须与交易日相同。
报告独立写出，输入库以 `mode=ro` 打开，命令不执行采集、模型或通知。

按以下顺序阅读 JSON：

1. `checkpoints`：指定时点是否有真实观察；未来检查点不能参与统计。
2. `consumers`：预期时段数、实际完成记录、缺失记录、耗时 p95、最后一次积压。
   缺少记录不自动证明服务未启动，也可能是在途、异常退出或缺少日志。
3. `symbols[].price_discovered_at` / `news_search_started_at`：发现及补查开始。
4. `evidence_members`：收到新闻、公告发布时间、归入事件的时间；尚无原文也可检查。
5. `events`：精确关联的官方正文与分析阶段时钟，不能用同股票其他事件的完成时间代替。
6. `queue_jobs` / `reasons`：排队、输入缺失、重试、排除、过期的具体原因与任务 ID。

原分析 worker 仍只在 08:00-11:59 ET 每 10 分钟运行。消费者分钟推进不等于全天分钟
分析。遇到 PENDING 必须结合调度、预算和运行记录判断，不能仅凭排队状态断言容量不足。

## 验收边界

- 历史状态从 transitions 重建，不读取今天的最新 checkpoint 冒充过去状态。
- 单日观察截止不超过交易所收盘，之后补到的证据不倒填进当日盘中验收。
- 缺失阶段返回 null；不会为旧记录补造首次时间。
- 延迟分位数只统计有记录的阶段，附样本数；未完成任务仍在明细中，不因没进入分位数而消失。
- 当前没有完整市场真值，因此 `market_recall=null`、`strategy_accepted=false`。
- 本报告不核准成交量、相对量比、Strong/Moderate、交易触发或送达情况。
