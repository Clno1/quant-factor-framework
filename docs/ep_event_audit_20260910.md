# EP 事件解读：引用与数量表达离线补强

## 本轮结论

本轮仅使用上一轮 PLAB、NYAX 两份真实 Kimi 响应及其已提供正文。新增独立 `ep-event-audit-v1` 审计，不修改 `ep-event-interpretation-v1`、历史响应、请求键或账本。

**六条原始解读中，五条被识别出硬性问题而拦截，一条仍待审核；没有任何条目获准自动发送。** 这不是五条内容造假，而是输出范围或引用不完整。

没有 API 请求、密钥读取、预算预留、SG 部署、定时任务或 Discord 推送。累计预算未因本轮增加。

## 新检查怎样工作

### 数量表达

`src/breakouts/ep/llm_event_audit.py` 的 `quantity_expressions()` 返回数量表达的原始文字和字符位置，覆盖本轮中文数量、中文日期、百分数、大写数词、全角数字和常见英文数量写法。例如“二十万处”“二零二六年第四季度”“零点五零美元”“壹佰萬元”“twenty percent”。

“一次性收益”“一致预期”“一体化”等普通词不因含有“一”而被当作数字。检查只表示违反本轮定性文本范围，不证明数字错误，也不承担期间、单位或金额换算验证。它仍是有边界的表达识别器，不承诺识别所有同义改写、分隔写法或所有语言。

数量本身并非最终 EP 报告禁区。可靠数字应来自独立核验的财务观察单元或程序生成的行情/覆盖字段，而不是模型在自由文本中重新抄写。

### 逐条结论引用覆盖

不把“引用 ID 存在”当成“引用正确”。本轮逐条对照原文，建立本地复核标注：

`原始输入 packet_hash → 原始条目全文、类别及引用 → 结论片段 → 所需证据段落与原文`

程序检查结论片段和证据原文的位置是否唯一、标注是否重叠、所需段落是否真的被该条目引用，以及是否还有未标注的文字。文档、条目、引文或 ID 改变时，旧标注不能悄悄沿用。删除一个标注不会让遗漏消失，而会留下 `unreviewed_spans`。

标注关系是本轮阅读原文后显式给出的，不是从关键词自动推断，也不是让同一模型自证。源文件为 `reviews/2026-09-10-ep-span-selection/event_source_review.py`，固定标注副本为 `tests/fixtures/ep_event_review_bindings_20260910.json`。模型输出不能作为可信标注传入。

`claim_inventory_complete` 只表示条目文字是否全部映射到复核标注；即使为 true，仍可能漏引所需段落，也不代表机器已证明语义。没有标注的新公告保持待审，不自动放行。

## 两个真实案例的结果

| 条目 | 旧检查 | 新检查 | 具体原因 |
| --- | --- | --- | --- |
| PLAB 事件数字摘要 | 拒绝 | BLOCKED | 财务数字超出定性协议；本轮没有为这一长条目补全语义标注 |
| PLAB 业务与利润比较 | 通过 ID/范围 | BLOCKED | 两处结论需要 p0014，但原响应漏引；“两大业务板块”也含数量表达 |
| PLAB 信息缺失说明 | 拒绝 | BLOCKED | 覆盖统计“157 段、6 段”仍超范围；缺失性断言未核准 |
| NYAX 收购事件 | 通过 ID/范围 | BLOCKED | 中文数量“超过二十万”被识别；不能绕过范围限制 |
| NYAX 业务互补解读 | 通过 ID/范围 | REVIEW_REQUIRED | 已标注结论的证据均引用 p0006，仍未获得自动语义核准 |
| NYAX 交割不确定性 | 通过 ID/范围 | BLOCKED | 中文日期被识别；“提供段落未包含……”仍作为未覆盖结论显示 |

PLAB 的两处漏引分别是“IC 与 FPD 两大业务板块呈现相反走势”和“FPD 下滑”。所需证据是 p0012 的 IC 增长和 p0014 的 FPD 下降，不是用同段中的任意数字替代。

更重要的协议问题：PLAB 原条目同时包含 GAAP、Non-GAAP、IC、FPD，完整引用需要 p0008、p0010、p0012、p0014 四段，但原协议每条最多三段。下一版应拆成更小的断言，不能通过只增大引用上限或把四个结论挤在一起解决。

NYAX 的业务互补解释原文确实有公司对支付网络、智能停车、扩张和交叉销售的表述。本轮标注保留原文的未来时态与条件；“已签约”不会被等同于“已交割”。但这些绑定并不是普适的跨语言语义验证算法。

全部条目仍保持 `semantic_support_verified=false`，不用于评级或推送。

## 扩大样本前还缺什么

本轮交付的是可审计的离线检查，不是新的生产模型协议，也没有扩大付费测试。下一版应让模型每条只提出一个可核对的断言，明确区分公告事实、管理层预期和推断；数量字段走独立验证，覆盖说明由程序生成。

先用这些已留档错误验证新版断言结构，确认每个结论都有对应证据且未知情况保持待审，再进行有界小批量调用。新公告没有本轮标注关系时，不能套用 PLAB/NYAX 的结论，也不能因没有被正则拦截就宣称通过语义验收。
