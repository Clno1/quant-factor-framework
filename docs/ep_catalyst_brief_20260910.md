# EP 事件摘要 v1：不再等待全面财务提取

## 本轮完成

新增可直接运行的只读事件摘要，读取现有 EP 候选、新闻线索和匹配原文。
不需要营收/EPS 提取通过，也不读取或请求 LLM。当前是**基于既有分类器的模板版**，
不是已经上线的 LLM 自由分析，更不是复刻截图里的 Strong/Moderate 评级。

摘要会展示：

- 发现了什么事件类型，以及公司是报告公司、收购方还是其他角色线索。
- 原文标题与链接、公告日期、供应商时间、取得原文时间。这几个时间不混用。
- 公告是否在当前交易观察窗口，还是旧公告、窗口边界或时间冲突。
- 尚无匹配原文的新闻/日历线索，单独标注为未经核准，不冒充直接催化。
- 展示数量上限、被折叠的法律通知，以及尚未核准的项目。

现有人工财务复核仅证明人工提交过带引用的断言，不能直接提升为自动核准事实。
本轮所有 `financial_claims` 为空，不输出具体超预期比例、一次性收益调整或自动评级。
原文标题可能包含数字，但会明确标注为来源标题，不当作摘要已验证的结论。

## 运行线路

```text
EP 数据库（只读）
  -> candidate_dossier：按候选、文档版本、实际收到时间选取证据
  -> classify_catalyst：复用已有事件类型、角色与时效检查
  -> source_brief：匹配原文的事件摘要
  -> headline_hints：尚未取得匹配原文的线索
  -> JSON 或中文纯文本报告
```

**没有经过财务提取、观察单元解析或模型调用，也不会等待它们成功。**
这让第一层“有何事件线索”能够独立阅读，第二层“精确数字及其影响”继续严格审核。

## 使用命令

JSON 模式与明确的观察时点：

```bash
/tmp/quant-ep-v1a-test/bin/python scripts/run_ep_radar.py --db data/ep/research_shadow_20260908.sqlite3 brief NYAX --format json --as-of 2026-09-10T04:25:00+00:00
```

没有可见候选时会返回 `NO_VISIBLE_EVIDENCE`，意思是当前采集范围与时点内没有证据，不是“该股票没有新闻”。
默认 `data/ep/observations.sqlite3` 并非这份归档库，因此上述命令显式指定数据库。

## 接下来仍缺什么

要得到截图那样的分析，还需要让 LLM 对少量候选的可靠正文做有引用的事件解读，
接入同一预算、去重与响应留档流程，再验收“事件摘要”的事实准确性。
不应重新要求每篇新闻先完成所有财务字段提取，但也不能用模板的事件分类代替真实 LLM 验收。
新摘要仍不认定价格上涨原因，不计算盘前量比或开盘买点，不自动发送。
