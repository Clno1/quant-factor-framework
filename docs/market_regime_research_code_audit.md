## 一、结论

本轮不是只看“测试是否通过”，而是按数据从下载到产物发布的完整路径重新检查：

```text
配置
  -> FMP / Cboe / FRED 原始数据
  -> available_at 与交易日覆盖
  -> PIT 成分重建和发布
  -> 标签与特征
  -> 输入清单
  -> 不可变研究产物
```

复审共确认并修复：

| 等级 | 数量 | 当前状态 |
| --- | ---: | --- |
| 高风险 | 3 | 已修复并有反例测试 |
| 中风险 | 6 | 已修复并有反例测试 |

没有发现远程命令执行、SQL 注入、模板注入、反序列化或密钥写入问题。该模块没有

## 二、已修复的高风险问题

### MR-01：过期或中间缺失的价格缓存可以被当成 PASS

**原问题**

旧校验只要求首尾日期相差不超过 7 天。一个缓存即使缺少中间数月，或者最新交易日
落后数日，仍可能进入研究。运行入口也只拒绝未来日期，不拒绝过期数据。

**风险**

- 最新市场状态并非当天状态；
- 滚动收益、波动率和标签可能跨越缺失区间；
- 研究 run 仍显示 `SUCCESS`。

**修复**

- 按 XNYS 日历生成配置区间内的完整交易日；
- 每个指数和 ETF 必须逐日完全匹配，缺 1 日也失败；
- 统一采用 17:00 America/New_York 作为市场核心数据截止时间；
- 17:00 前不把刚收盘但 Cboe 尚未发布完整值的当日作为研究日；
- `prepare` 和 `run` 都重新执行覆盖率校验。

**回归测试**

- 缺少区间中间交易日时强制失败；
- 未来或尚未到 `available_at` 的日线强制失败；
- 真实 7 个市场序列与 XNYS 交易日逐日匹配。

### MR-02：Cboe/FRED 缓存可绕过 available_at 契约

**原问题**

新下载的数据有基本解析校验，但复用本地缓存时没有完整验证 OHLC、数值和
`available_at`。FRED 文件还可能包含已经下载、但在当前时刻尚未发布的观测。

**风险**

- 当前交易日可能使用 17:00/18:00 以后才知道的数据；
- 同一个文件在不同运行时间产生不同特征，破坏可重复性；
- 损坏缓存可能被写成 `quality_status=PASS`。

**修复**

- Cboe 每个指数强制检查完整 OHLC、正数、`high >= low` 和 17:00 可用时间；
- FRED HY OAS 强制检查非负数值、下一工作日 18:00 的保守发布时间；
- `prepare` 只保存准备时已经可用的信用观测；
- `run` 发现未来可用行时失败，不做静默过滤；
- Cboe 三个期限指数都必须更新到本次研究截止日。

### MR-03：任意同名 PIT 文件可以绕过重建质量门禁

**原问题**

PIT CLI 只在重建时检查 `quality_status`，完整研究运行只检查生产路径下是否存在
`SP500.parquet`。手工放入同名文件即可绕过事件一致性检查。

**风险**

静态当前成分、被修改的成员文件或失败候选都可能被误认为 point-in-time 股票池，
产生严重幸存者偏差。

**修复**

生产发布现在同时生成：

```text
data/pit_universes/SP500.parquet
data/pit_universes/SP500.metadata.json
```

元数据绑定：

- `quality_status=PASS`；
- 严格模式证明；
- 重建 `asof` 和起始日期；
- 成员文件 SHA256；
- 完整诊断；
- FMP 当前成分和历史事件输入哈希。

完整研究运行会重新验证状态、日期、诊断和文件哈希。缺元数据、候选模式、哈希
变化或诊断不干净都会失败。

## 三、已修复的中风险问题

### MR-04：来源清单记录哈希但运行时不核对

旧 run 同时保存了来源清单和实际文件哈希，但没有证明两者一致。现在每个实际使用
的价格、Cboe 和可选信用文件都必须在来源清单中有且只有一个 PASS 条目，SHA256
必须匹配，否则要求重新 `prepare`。

### MR-05：跳过信用时仍可能把信用文件记成输入

旧逻辑只要磁盘存在 `credit.parquet`，即使使用 `--skip-credit` 也会把它写入 run
输入清单。现在输入清单只记录真正参与计算的文件。v6 核心 run 的输入为 7 个价格
文件和 1 个 Cboe 文件，没有信用文件。

### MR-06：`--asof` 可把当前成分冒充任意历史快照

FMP 成分接口返回当前集合，不是指定日期快照。旧 CLI 接受任意 `--asof`，可能把
今天的集合标成过去或未来。现在显式 `--asof` 必须等于最新已完成 XNYS 交易日；
历史状态只能由事件反推，不能修改日期标签得到。

### MR-07：产物发布允许特征与标签日期错位

直接调用发布 API 时，旧代码没有强制特征和标签索引完全一致。现在要求：

- 两个索引唯一且递增；
- 日期逐项完全一致；
- 特征注册表顺序与特征列顺序一致；
- 特征矩阵不存在正负无穷；
- JSON 使用临时文件加原子替换。

### MR-08：配置窗口和文件名边界不完整

新增校验包括：

- 标签、波动率、均线、相关性和动量窗口必须为有效正数；
- `high_lookback >= minimum_history`；
- 动量 `lookback > skip >= 1`；
- 概率、回撤和屏障阈值必须处于合理区间；
- 标的开始日期不能晚于结束日期；
- PIT 股票池名称必须是安全的单一 ASCII 路径组件；
- 根目录不能是空路径、`.`、`..` 或 `/`。

### MR-09：序列化 PIT 事件和同日聚合事件存在边界缺口

候选事件写入 Parquet 时，`reason_codes` 会变成 JSON 字符串。重新加载后旧代码可能
把字符串拆成字符列表。现在会严格反序列化并验证列表类型、`source_row` 和状态值。

另外，同一天不同源行中出现同一 ticker 同时新增和移除时，现在会作为聚合身份歧义
失败，不再依赖后续集合运算偶然发现。

## 四、数据质量发现

### DQ-01：Cboe 官方老 VIX OHLC 有 47 行不满足常规包含关系

真实文件检查发现：

| 序列 | open/close 不在 high/low 内的行数 |
| --- | ---: |
| VIX | 47 |
| VIX9D | 0 |
| VIX3M | 0 |

异常集中于老 VIX 历史。系统当前只使用 Cboe 收盘值，因此没有删除或人工修改官方
数据；仍要求所有值为正且 `high >= low`，并把异常数量写入来源清单。若未来加入
VIX 日内振幅特征，必须先单独处理这些历史口径。

## 五、公式与前视偏差复核

### 5.1 标签

检查通过：

- 候选日资格、滚动高点、回撤分位和波动屏障只使用 T 日及以前数据；
- 自适应底部阈值使用 `shift(1)`，不让 T 日观测决定自己的极端阈值；
- 未来数据只进入标签、MFE、MAE 和触碰日；
- 同一未来日线同时穿越上下屏障时输出 `ambiguous`，不猜盘中顺序；
- 最后不足完整 horizon 的日期不生成虚假标签。

### 5.2 动量压力

复核后确认原有一日移位没有同收盘价问题：

```text
score(t) = price(t-skip) / price(t-lookback) - 1
formation_score(T) = score(T-1)
```

配置强制 `skip >= 1`，所以 `score(T-1)` 最新只使用到 `T-2` 或更早的价格，在
获得 `T-1 -> T` 收盘收益前已经可知。测试同时证明 T 日价格冲击不能改变 T 日
winner/loser 分组。

### 5.3 其他特征

检查通过：

- ETF 收益使用总回报价格；
- Amihud 分子使用总回报，分母使用真实市场收盘价乘成交量；
- 指数 vendor volume 不用于 Amihud；
- 波动率滚动分位只统计已经出现的观测；
- breadth 日收益要求股票在 T-1 和 T 都属于 PIT 股票池；
- 动量分组使用滞后排名；
- 信用特征先按 `available_at` 对齐，再有限前向填充，最多 5 行。

## 六、仍未解决的风险

### R-01：真实完整 PIT 模式仍未通过

FMP 1990 年以来事件仍有 23 组无法闭合：

- 2 组无法分类；
- 9 组新增后在后续状态缺失；
- 12 组 ticker 复用、继承或缺少后续加入。

生产 PIT 文件未发布，这是正确的失败关闭行为。需要稳定证券实体 ID 或第二个可
审计来源，不能人工把成员数量修到约 500 后放行。

### R-02：FRED HY OAS 尚未接通

当前网络下 FRED graph CSV 返回 504，因此最终真实 run 使用
`--skip-credit`。HYG/LQD 代理存在，但不能宣称已经包含官方 HY OAS。

即使恢复下载，当前 FRED 适配器也不是 revision-vintage 数据源。后续若使用会修订
的宏观序列，必须另建 vintage 数据契约。

### R-03：完整横截面性能尚未用真实历史并集验证

breadth、60 日平均相关性和动量压力已有因果单元测试，但由于生产 PIT 和退市股票
历史尚未通过，完整 500 股、30 多年数据的运行时间、内存和最终覆盖率尚未验收。

### R-04：下一阶段必须处理重叠标签

连续多天可能同时是顶部或底部候选，5/20/60 日标签也彼此重叠。这不是标签生成
错误，但后续事件研究和模型验证必须使用事件去重、purge/embargo 和 walk-forward，
否则显著性与样本外结果会被夸大。

### R-05：相关性成员口径需要在模型阶段冻结

当前 60 日相关性定义为“用 T 日成员的过去 60 日价格计算相关性”，允许使用其加入
指数前的公开价格。这是可解释且无前视的口径，但也可以选择“60 日持续在池”的更
严格定义。正式 scorecard 前必须固定一种，不允许看到结果后切换。
