# EP 截图案例对照与验收矩阵

日期：2026-09-06。配套：[数据能力报告](ep_data_capability_audit_20260906.md)、[第一版范围](ep_v1_scope_acceptance_20260906.md)。

## 1. 先回答：能否找到同样的股票、写出同样的分析？

**事件线索基本具备；盘前行情和深入解释还没有全部具备。不能据此承诺相同名单、相同等级或相同提醒时间。**

本次按截图给定名单查询了 17 个正式告警，均找到相关财报、并购或合同公告，FMP 标注的发布时间均早于对应截图时刻。15 个财报案例也取得实际值和预期值。这个结果说明“查这些公司时能找到线索”，不是“全市场扫描已经自动找到了 17 只”。

所有案例均缺少可核验的历史盘前分钟量。本轮没有重建截图的盘前涨幅和量比，也没有运行 EP 评分器、杯形重检或分钟突破回放。因此表中的 Strong、Moderate 均是**截图标签**，不是本系统计算结果。

时间暂按截图显示的中国时间换算为美东时间，FMP 无偏移的日期字段暂按美东解释；这仍是需要原始时间戳交叉确认的假设。事后接口中的 publishedDate 早于提醒，不证明供应商当时已经交付，也不证明预期值没有后续修订。

## 3. 这批案例对规则设计提出的要求

### 3.1 不能只有“盘前涨幅至少 10%”一个入口

截图中的 CRWD 9.4%、DG 7.5%、SAIC 8.2%、DELL 8.8%、AGX 5.5%、AVAV 7.0%，都低于 10%。若全市场发现的第一道硬门槛固定为 10%，就会排除这六个已知例子。

第一版应采用“行情异动发现”和“新公告发现”两个入口的并集。财报/重大公司事件可以先入观察，不需要先满足 Return20 >= 20%、ADR >= 6%、日线杯或大于 10% 的 gap。后续才分别判断催化质量、行情质量和交易条件。

这不是为了硬凑截图而把交易门槛降低。**进入候选、值得提醒和可以买入是三件事。** 发现入口可以宽，正式提醒和触发必须保留质量闸门。

### 3.2 VEEV 要有“薄量观察到开盘后升级”这个状态转移

截图的补发时间按上述时区假设是 8/27 09:36 ET，已经开盘六分钟。它提供的是开盘后量能建立时再提醒的例子，不是每天仅运行一次盘前筛选。

拟实现行为：财报发现后保留候选；盘前量未知或不够，标记等待；开盘后使用**常规时段同钟基线**重新评估，符合条件才发送状态升级。盘前 1.29x 和开盘后 8.22x 必须各自注明窗口，不能自动认为是同一个指标增长了六倍。

09:36 的候选升级也不等于已突破 ORH。本轮没有证明该时刻符合价格触发规则，验收不能要求代码“为了匹配截图时间”硬发买入信号。

### 3.3 AGX 的“催化强”与“可交易”必须分开

截图本身将 Strong 与盘面薄并列。我们的输出应至少分成 `catalyst_quality`、`liquidity_status`、`trigger_status`，否则一个 Strong 会掩盖数据缺失或低成交量。

AGX 与 GTLB 的开盘缺分钟必须留下 `OPENING_RANGE_DATA_INCOMPLETE` 等原因。不能把找不到开盘 bar 转成价格为零，也不能随意把 09:32 当成开盘第一分钟。NYAX 亦应区分“供应商未提供记录”和“确实无成交”。

### 3.4 同样的中文分析，需要全文和跨期比较

基础财报数字可以从结构化接口取得，但“ARR 重新加速”“回购推动 EPS”“一次性税项”“收购是买方还是卖方”不是简单的涨幅和新闻标题分类。

需要保留有来源的原文片段、指标期间与口径；计算交给程序；LLM 用于结构化抽取和解释。没有来源的“whisper”“空头逻辑被打破”“流动性无忧”，不应为了文风类似而生成。

GTLB 官方表同时列出不同每股收益口径；DELL 同比 EPS 增长与相对分析师预期的 surprise 也不是同一个百分比。验收目标应是**事实可追溯且口径正确**，不是逐字复刻截图。[GTLB 官方财报](https://ir.gitlab.com/news/news-details/2026/GitLab-Reports-Second-Quarter-Fiscal-Year-2027-Financial-Results/default.aspx)、[DELL 官方财报](https://investors.delltechnologies.com/news-releases/news-release-details/dell-technologies-delivers-second-quarter-fiscal-2027-financial)。

### 3.5 “不是当天发布”不自动等于旧消息

盘后财报的下一交易日早晨仍然是主要评估窗口。AVAV 的供应商公告时间是前一日 15:15 ET，需要检查是否有尚未完成的价格发现，而不是只抓午夜以来的消息。

事件应保存首次公告、重大修订、首次观察、已经提醒的阶段和经历过的交易 session。重发旧公告不能重置事件时效；上一日盘中事件可以保留观察，但应明确标注“延续”，不能假称今天新发生。

## 4. heads-up 和排除案例也要成为测试样本

以下不是全部已完成原文审计。表中明确区分本轮实测和后续待验证，不能把截图标签直接当负样本真值。

| 案例 | 本轮掌握的证据 | 应测试的系统行为 |
|---|---|---|
| EOSE 9/2 | FMP 查到 08:00 的 MN8/Google/100MWh 项目消息 | 是公司直接参与的事件；合同金额未知时，不能断言不足以支撑 12% 涨幅 |
| SOLS 8/28 | FMP 查到 8/27 17:00 的并购终止消息 | 区分公司直接事件与经营型财报 EP；不是“没有催化” |
| PSNYW 9/2 | profile 可取，但公司名和非 ETF 标志不足以识别权证 | 证券类型应先排除权证；不能因名字关联 PSNY 就当普通股 |
| CRM 8/27 | FMP 查到前夜财报以及合作消息 | 直接事件存在；经营质量与一次性收益另外分析，不先照抄 heads-up 结论 |
| NVDA 8/27 | 历史新闻两页各 100 条，最早仍只到 8/26 16:45:40 | 尚未覆盖更早财报发布时刻；分页没查全不能判定“无新消息” |
| HCM / IMTX / IVA / MESO | 本轮未逐项核验事件全文 | 生物科技二元风险属于可配置策略政策，不是所有这些股票都没有催化 |
| BEKE / UMC / SEDG / PURR | 截图称政策、行业或加密联动；本轮未完整核验 | 需要公司直接事件检索加板块证据；只有相关性不能证明主题就是上涨原因 |
| FLNC | 截图称旧利空后的反弹；本轮未完整核验 | 要对照此前指引、事件时间与后续修订，不能用一个标题判旧消息 |
| DAKT | 截图称量比不足；真实同钟量尚未取得 | 保留观察或明确因缺数据等待，不能把量未知写成量不足 |
| VMET、EMAT/SRAD、TE 等尾部备注 | 截图部分文字截断，实体及行情未逐项核验 | 先核对准确代码和证券身份，不擅自更正代码或推断“无 gap” |

EOSE 的直接参与关系可对照[公司公告](https://investors.eose.com/news-releases/news-release-details/mn8-energy-google-and-eos-energy-enterprises-bring-advanced)。NVDA 财报的原始日期可对照[发行人公告](https://investor.nvidia.com/news/press-release-details/2026/NVIDIA-Announces-Financial-Results-for-Second-Quarter-Fiscal-2027/default.aspx)；不能仅因为是前夜发布，就把次日早晨排为旧消息。

此外，对方“昨日清单 #21 / #26”、私人持仓、隐藏排除名单和编辑前消息不在公开输入中，不能承诺复现这些上下文。

## 5. 当前验收结果与后续测试方式

| 验收项目 | 本轮结果 |
|---|---|
| 给定 17 个案例能否查到相关公告线索 | 17/17，已取得 |
| 15 个财报案例能否查到实际值/预期值 | 15/15，当前修订快照；并非事前版本 |
| 能否还原 17 个截图时刻的盘前涨幅与同钟量比 | 未通过，缺历史扩展时段证据 |
| 能否统一核准全部指引、ARR/NRR、税项等解释 | 未通过，全文访问和结构化抽取未完成 |
| 事件日常规分钟记录是否存在 | 17/17 存在；3 个有分钟标签缺口，全部存在日线/分钟量差异 |
| 全市场盲扫能否自动发现这些股票 | 未测试，本次按给定名单查询 |
| 是否产生相同 Strong/Moderate 等级或分钟触发 | 未测试，EP 规则和运行服务尚未实现 |

下一步把这些案例制作成有来源的固定输入测试集，验证去重、时间、财务口径和状态转移。再选择没有用于调参的交易日做全市场验证，并保留所有进入、等待、排除和超出容量的候选。

截图只显示对方选择发出的消息，不是完整市场真值集；因此不能把“对方没发但我们发了”一律计为误报，更不能从名单一致率推导收益能力。
