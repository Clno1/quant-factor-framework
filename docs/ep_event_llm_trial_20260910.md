# EP 带引用事件解读：小样本验收

日期：2026-09-10。范围：两份归档公告、Kimi 真实调用、独立 SG 验收目录。没有开启定时任务、自动评级或 Discord 推送。

## 1. 本轮完成什么

新增 `src/breakouts/ep/llm_event.py`，采用 `ep-event-interpretation-v1` 协议。让模型阅读少量可靠正文段落，提出 EVENT（事件）、INTERPRETATION（可能影响）和 UNCERTAINTY（不确定性），每条附原文段落 ID。

本轮刻意先验证定性解读，不让模型重新抄写营收、EPS、比例、日期，也不判断股价原因、时效或 Strong/Moderate。数字事实仍应走此前绑定期间、主体和口径的独立验证路径。此限制不代表最终报告不能包含数字。

完整 Prompt 位于 `src/breakouts/ep/llm_event.py` 的 `RULES`。每次最多四条，每条最多 350 字符、引用一至三个段落；只接受显式选择的至多十二段输入，不静默截断正文。

本轮人工选择 PLAB 的六段、NYAX 的四段，分别来自 157 段和 41 段的归档正文。不是自动全市场发现，也不是全文覆盖或新鲜度验收。

## 2. 实际执行链

`可靠归档正文 → 显式段落选择 → event-plan 零请求预检 → 预算与请求键核对 → event-run → Kimi → 原始响应留档 → ID/范围校验 → 人工对照原文`

- `llm_provider.py`：为新协议提供独立响应 schema，复用原有 Kimi 传输。
- `llm_service.py`：复用预算预留、幂等去重、错误记录和原始响应账本；本地输入另存为 `event_packet`。
- `reviews/2026-09-09-ep-llm-trial/run.py`：新增 `event-plan`、`event-run`；真实执行必须提供预检请求键和 `--execute`。
- `tests/test_ep_llm_event.py`：验证输入不变、范围限制、文档版本、共享预算、去重、留档和 CLI 不意外读取密钥，并离线回放两份真实响应。

仅更新 `/home/projects/quant/tmp/ep-llm-trial-20260909` 中的验收源码，使用 `/home/projects/quant/.venv/bin/python`。未更新生产服务源码、未重启服务、未提交远端 main。

| 公告 | HTTP / 完成状态 | 输入 / 输出 tokens | 模型条目 | 通过 ID/范围检查 | 被拒绝 |

**四条通过检查，不等于四条被原文完整支持，更不等于四条可发送。** 所有结果仍是 `semantic_support_verified=false`、`eligible_for_rating=false`、`DISABLED_SHADOW_ONLY`。

PLAB：模型仍在事件条目输出了财务数字，被范围检查拒绝；另一条因包含“157 段、6 段”等覆盖数量被拒绝，这属于过宽的范围拦截，不能称为财务幻觉。唯一通过的条目提到“FPD 下滑”，输入的 p0014 确实支持，但模型没有引用 p0014。因此“引用 ID 都存在”不足以证明整句引用完整。

NYAX：业务互补的解读较好，明确归因于公司表述，并用“可能”“拟”描述整合、扩张和交叉销售，没有把签约说成已经交割。但另外两条分别含“超过二十万”“二零二六年第四季度”，绕过了只检查阿拉伯数字等符号的 v1 范围检查。原文部署数量为超过 250,000 处，模型的更粗表述虽然不必然矛盾，仍不符合本轮禁止数量陈述的协议。

NYAX 的“提供段落未包含……”也只能描述这次片段覆盖，不能推断完整公告或其他披露没有这些信息。当前不进行自动语义核准。

## 5. 下一步边界

先离线改进每条单一断言与完整引用检查，并将数量、期间等字段与定性文本分离。中文数词不能被当成规避数字限制的途径；覆盖统计应由程序生成。不能靠继续追加几条正则就声称解决了语义核验。

涉及财务比较时，应引用已核验的财务观察单元；无法证明支持关系的定性结论继续待审，不自动改写成“已验证”。使用这两份真实响应做新版协议的对照回归，保留 v1 的历史检查结果，不追改账本。
