# 行业中性化接入多因子研究与分类观测归档计划

日期：2026-09-08。

版本：v2。交付目标是将行业中性化接入日常单因子研究、多因子合成、策略回测与模拟盘目标计算；对照报告是验证环节，不是最终交付终点。

状态：修改方案已完成，尚未实施下述代码、配置和部署改动。本计划不宣称真实对照研究或主流程接入已经完成。

## 1. 本次决策

- 使用已有 FMP 权限和项目数据，不新增数据采购。
- 第一版采用 FMP `sector` 大类。历史研究使用固定快照近似；未来每日计算使用决策时刻可得的归档观测，并记录每次实际使用的版本。
- 同时完善分类观测归档。复用每日证券主表流程的已有抓取，不建立重复的全市场采集任务。
- 当前分类回填明确使用 `CURRENT_SNAPSHOT_APPROXIMATION` 标记。既不伪造历史生效日期，也不改成 `PIT_EFFECTIVE_DATED`。
- 行业中性化成为统一预处理中的可配置步骤。行业相对选股研究使用中性化方案，同时保留不做中性化的对照方案及明确的因子级覆盖设置。
- 单因子分析、置信评价、多因子合成、策略回测、研究页面和模拟盘必须消费同一处理方案与可追溯数据版本。功能接入属于本次交付；收益是否改善和是否替换已有冻结账户属于另外的研究与策略选择，不能混同。
- 系统必须能够识别、分析和控制行业暴露，但不预设所有因子都应无条件中性化。用于行业轮动的信号可以明确保留行业成分；因子行业中性化不保证最终组合行业权重等于 SPY。

## 3. 第一阶段：冻结分类与建立观测归档

拟新增 `src/data/classification_snapshots.py`，统一提供归档、校验、按快照 ID 读取和按观测时间查找的能力。另提供 `scripts/archive_classifications.py`，用于导入已有归档、处理指定主表版本和人工重试。

### 3.1 数据范围与来源

优先读取已验收的证券主表 generation 及对应 FMP profile 输入，保留美国研究证券及历史身份映射。快照至少覆盖本次回测中出现过的证券身份，不能只取今天的 SP500 成分或当前持仓。

分类按稳定 `security_id` 保存，ticker 作为带日期的别名。仅公司 CIK 相同不足以自动合并类别股。改名、代码复用、分拆与合并继续遵循已有身份规则。

旧股票没有可核实分类时保留 UNKNOWN；如果使用已有旧观测作为补充，必须逐行标出原始观测时间和来源，不能称为本次新抓取。第一版也不得自动用相似公司、行业名称猜测分类。

### 3.2 归档内容

建议根目录：`data/lake/classification_observations/`。

- 快照数据：security_id、原始 sector/industry、分类体系与版本、行级来源/观测时间、缺失或冲突状态。
- 身份数据：本次使用的主表和 symbol history 版本、哈希；必要文件按内容哈希保存一次。
- 清单：snapshot_id、归档 schema、供应商端点、源文件哈希、主表 generation、取数开始与结束时间、归档创建时间、行数与覆盖统计。
- 新批次使用完整取数完成时间作为保守的可用时间；按日使用时从后续交易决策开始生效。
- 复用已有输入时保留原始来源时间，不能用重跑时间刷新其信息新鲜度。
- 对旧归档，仅在哈希、来源和写入流程可验证时，以源文件创建/保存时间作为保守的已记录时点，并明确 `ARCHIVED_SOURCE_TIMESTAMP`；不能据此推断供应商更早公布时间。
- 若无法验证旧归档时点，仍可用于当前快照近似实验，但不能放入未来的按观测时点回放模式。

数据采用不可变文件和原子更新的索引。同一上游版本重复执行不生成伪造新观测。若新一次实际取数内容相同，可复用分类 payload，但保留该次观察成功的记录。

保存每次实际观测的新增、改类、缺失和冲突列表。“在两个观测之间分类不同”只说明变化发生在该区间，不能把后一个观测日伪装成业务实际变更日。

### 3.3 持续保存

在现有每日证券主表步骤完成后调用归档逻辑，不新增重复的定时采集和额外全市场请求。正常新源抓取使用现有批量接口；NOOP 或重试时复用相应归档，不冒充新抓取。

只发布通过身份与来源检查的研究可用快照。失败时保留失败诊断和上一份已验收快照，明确数据时间与陈旧状态；归档失败不回滚已经成功发布的行情，也不触发交易重放。既有运行报告中增加归档状态、最后成功时间和覆盖情况，不新建外部通知渠道。

必要分类数据及索引放在长期数据目录，不能只依赖可能清理的 outputs 目录。原始供应商文件沿用已有审计保留策略，归档保留实际用于计算的分类、身份映射和来源哈希，保证旧实验可复现。

## 4. 第二阶段：统一预处理与主流程接入

### 4.1 统一处理方案

拟新增 `src/preprocessing/policy.py`，定义不可变的处理方案（具体字段名可随仓库约定调整）：是否启用行业中性化、分类体系/粒度、历史分类模式、未来观测选择规则、因子级覆盖、最少样本、缺失处理、方法版本。

策略保存处理规则；每次研究和每日目标计算保存当次解析出的分类 snapshot/hash、证券身份版本、因子 generation 与处理方案哈希。这样未来每天可使用新的已知观测，同时旧结果仍能按旧输入复现。

普通历史对照支持 `none` 与 `current-snapshot`；有合格历史数据时保留 `pit`；未来按归档观测执行使用明确的 `observed-asof` 语义。不能用全局 CONFIG 的临时修改来控制某个用户请求或某个账户。

### 4.2 每个因子在进入单因子检验和合成之前处理

主流程统一为：历史股票池/证券身份及输入对齐 → 原始因子 → 去极值 → 按方案行业中性化 → 横截面标准化 → 单因子评价/多因子加权 → 策略回测和目标计算。

`preprocess_factor` 接收显式方案和已验证分类上下文。复用现有逐日回归内核，同时保留严格 PIT 校验；当前快照方案通过明确的非 PIT 入口计算。输出审计说明实际应用的日期/股票数，不能把“请求启用但被跳过”呈现为已中性化。

第一版使用项目现有 MAD3 口径，不同时改变因子原始定义、交易成本、市值处理或因子权重学习方法。单因子分组按注册方向解释，多因子合成保留现有有符号权重语义，避免重复翻转负向因子。

### 4.3 因子存储、评价和发布版本

扩展 `src/factors/artifacts.py`、`src/factors/publication.py`、`src/factors/data_publication.py` 及 `src/data/access.py` 的数据契约：因子身份不能仅由 factor_id 决定，还应绑定处理方案、分类版本、研究股票池及计算版本。

原始值与不同 clean 变体通过不可变 generation 并存。已有单目录覆盖式矩阵读取需要兼容升级为按方案/版本读取，不能生成中性化版之后让旧策略无声读到它，也不能让新策略继续读取未中性化旧产物。版本哈希必须进入增量计算指纹和研究发布的 NOOP 判定。

单因子 IC、分组收益、置信评价、相关性和下游用于选因子/定权的信息均绑定所评价的变体。新中性化因子不能复用旧未中性化 IC 或置信评分。若启用基于历史表现的权重估计，只使用决策时点已可评估的历史窗口，不用完整回测结果反推过去权重。

`scripts/run_mvp.py`、`scripts/run_factor_research.py`、`src/factors/broad_pipeline.py` 接受相同处理方案，日常任务能发布并更新中性化研究版本，而不仅由对照脚本临时生成文件。

### 4.4 多因子合成与共同样本

`compose_factor` 与 `adhoc_compose` 显式接收策略方案、分类上下文和预期因子版本；自选池与命名池使用同一计算逻辑。已中性化、未中性化组件的搭配只能由策略明示，不能因读取缺省值或缓存回退而偶然混合。

共同样本是实现重点：逐因子在各自样本中中性化后，再取股票交集，可能使交集中的行业均值重新偏离零。合成输入必须在本次统一成员/分类与全部组件可用掩码上计算或复核。掩码不同需要从绑定的 raw 重建对应输入，不能在旧 clean 上重复去极值和中性化。单因子研究的处理样本与策略合成样本区别应留在审计中。

保存 raw、clean、实际合成输入、各因子贡献与 composite，页面可解释最终排名来源。小股票池不能悄悄降低最少回归样本或自动关闭中性化；MAG7 等场景明确不支持该配置，后续需要更大的参考横截面时另行定义，不能借用未来或不明样本。

### 4.5 策略配置、页面、回测与模拟盘

扩展 `StrategyDefinition` 的版本化配置及序列化，行业处理作为策略可保存的设置；新行业相对选股研究采用中性化方案，不做中性化版本仍可选择。旧 schema 迁移明确对应原有处理方式，避免静默改变已有配方。

研究与策略页面支持选择行业处理方式、显示数据日期和近似假设，并能查看该方案对应的单因子和多因子结果；原始版与中性化版可以直接比较。不是只增加一张与策略计算无关的报告页面。

`src/backtest/runner.py` 与 `src/papertrading/target.py` 使用同一方案解析与合成入口。新模拟盘冻结策略处理规则；每次运行记录当次因子/分类版本，未来只消费决策前已获得的分类。历史复盘若指定当前快照近似，必须明确与当时真实决策复现分开。

纳入一次完整的多因子策略回测和模拟目标验收，证明分数、排名和目标权重实际消费了中性化输入。已有冻结账户采用新版本应走策略版本迁移或独立新版本验证，不自动清仓、重放旧交易或覆写既有账户历史。

因子中性化完成后仍报告实际组合行业权重。若要让组合与 SPY 的行业权重接近，需要组合构建层的行业约束；该能力与因子中性化分开定义，不能承诺本次残差处理就自动实现基准行业配平。

### 4.6 对照脚本作为统一流程的验收工具

对照脚本复用上述处理、发布和合成逻辑，不再维护一套仅能单独运行的算法。`scripts/run_industry_neutral_comparison.py` 保留单因子比较，并增加调用既有策略定义进行同权重多因子比较的入口。拟议分类参数：

```text
--classification-mode pit | current-snapshot
--classification-snapshot <归档清单路径>
```

保持现有 PIT 调用默认行为。近似实验显式选择 `current-snapshot`，并固定 snapshot_id/hash。启动时解析一次数据、因子、分类、身份和基准版本，运行过程中不追随 latest 指针。重跑同一实验使用相同清单，不因未来 profile 更新而改变过去结果。

示意命令（实现后使用）：

```bash
python scripts/run_industry_neutral_comparison.py \
  --universe SP500 --factor MOM_6M \
  --start 2020-01-01 --end <已验收数据结束日> \
  --classification-mode current-snapshot \
  --classification-snapshot <固定快照清单> \
  --output outputs/industry_comparison/<run_id>
```

矩阵构建方式：在历史每个日期，用当时 ticker 对应的证券身份，连接固定快照中的 sector。只固定分类，因子、价格、股票池成员和交易状态仍按历史日期变化；既有禁止回填的证券历史规则保持有效。

对照可以生成独立输出目录，但其计算方案必须是日常研究、策略回测和模拟目标计算能够直接选择的同一种方案。所有近似历史输出保留 `CURRENT_SNAPSHOT_APPROXIMATION` 和假设说明。

## 5. 第三阶段：公平对照与可读报告

保留三个版本：

1. `baseline_all`：全体原本可研究样本，不做行业中性化。
2. `baseline_matched`：有可用分类且能共同计算的样本，不做行业中性化。
3. `industry_neutral`：与第二组相同样本和可评估日期，做行业中性化。

主要效果比较为 2 对 3；1 对 2 单独说明分类缺失带来的样本选择影响。不能用分类可用性代替真实历史成员掩码处理退出和结算。

覆盖报告逐日输出：原始有效股票数、有分类股票数、共同样本数、行业数、行业样本规模、未知/冲突名单，并区分活跃和退出证券的缺失。

保留每日至少 30 个有效回归样本及自由度检查。95% 分类覆盖作为首轮完整覆盖目标；达不到时先定位缺口。若仍有足够样本，可以明确标为 `PARTIAL_COVERAGE` 的探索结果，而不把整段研究伪装为覆盖充分。严格 PIT 模式原有规则不受该近似模式影响。

新增一份 Markdown 汇总及机器可读文件，至少展示：

- IC、Rank IC 口径说明、IC 均值/稳定性和分年结果；沿用项目已有 IC 实现，避免另算不一致指标。
- 各分组及方向正确的多空结果，扣除项目现有成本后的收益、回撤和换手。
- 正向因子与负向因子按既定方向解释分组；不能把 VOL_20D 的最高原始分组自动称为优选组合。
- 根据 `position_daily`、`portfolio_daily` 的实际模拟仓位计算行业集中度，现金与未知分类另列。不能用目标分组股票数代替实际持仓权重。
- 同一固定分类快照下的最大行业权重和集中度变化。第一版不伪造 SPY 历史行业偏离；现有基准收益比较继续使用绑定的收益序列。
- 分类快照日期、源文件哈希、所有输入版本、回测参数、样本排除和近似假设。

先做 MOM_6M，验证基础计算后再做 VOL_20D、REVERSAL，并使用这些组件构成一套事前固定有符号权重的多因子策略，比较原始处理与行业中性化处理。研究效果比较不以样本内调权后的收益替代同权重对照。先覆盖 SP500，再做 NASDAQ100 对照。MAG7 股票过少，不作为需要至少 30 个样本的行业回归首轮验收池。

目标区间先固定为 2020 年至最近已验收数据日，并报告分年结果。区间因行情或退出结算等问题不可用时，记录独立原因，不按回测收益挑选区间。此前 SG 的 SP500 研究存在退出结算规则问题；执行前重新核查，近似分类模式不能掩盖该问题。其未解决时可继续归档、分类诊断和其他可用股票池实验，完整 SP500 结果仍需明确待完成。

## 6. 后续按观测时点回放

保存分类有必要：一方面能复现当前近似研究，另一方面以后可以回答“当时我们实际记录到的分类是什么”。

第一版就提供按观测时间选择已归档快照的基础读取能力：只选择在决策前已完成观测的记录，未来快照不能补写旧决策。在首个可信观测之前保留缺失；旧值延续时输出数据年龄和缺口信息。

这类数据应称为“归档观测历史”，与供应商发布的真实分类生效历史分别标记。未来样本积累后，可用它进一步检验固定当前分类近似的敏感性；不会因保存了一天快照就宣称补齐多年 PIT 历史。

必测行为：

- 固定同一快照时，新 latest 指针不会改变旧实验；文件改动或哈希不符必须被发现。
- 当前快照可以明确用于近似模式，但严格 PIT 模式继续拒绝。
- 改名连续身份正确连接；类别股、代码复用、冲突和缺失不能误连。
- 对照组与中性化组使用相同有效样本、日期与输入版本。
- 行业均值偏移在合成样本中被消除；单行业、极小行业和不足样本的行为明确。
- 负向因子的优选分组、实际持仓权重/现金口径正确。
- 归档重复运行不制造新观测；重用旧输入不改变原始观测时间；归档失败不更改已发布行情/账户交易状态。
- 按观测回放拒绝未来快照，并保留首次观测前的空白。
- 同一 raw 的原始处理版和中性化版可并存，版本、哈希和数据契约不能互相冒用；NOOP/缓存不能返回不同处理方案的旧产物。
- 单因子检验、置信评价和多因子组合引用正确变体；因子级缺失取交集后，实际合成输入仍满足所声明的行业处理口径。
- 策略保存/加载/归一化保留所有处理字段；旧配方迁移不变更其计算方式；有意保留行业信号的组件可明确配置。
- 命名池、自选池、CLI和页面回测在相同样本/输入/方案下给出一致结果；小样本请求不能显示成中性化成功。
- 至少一套多因子策略从页面或标准研究入口完成配置、因子版本选择、组合回测和模拟目标生成，验证分数/贡献/排名链条；同一决策输入下回测与模拟盘合成分数一致。
- 未来每日更新能采用新可得观测，历史运行仍能按原版本复现；失败或部分覆盖的探索结果不得自动成为模拟盘的可用研究证据。

测试顺序为新模块针对性测试、现有行业/PIT/证券主表/每日流程回归、真实数据样例对照，最后执行项目所需检查。测试结果与真实研究结果分别报告。

实施顺序为：分类冻结与归档 → 统一预处理方案与因子版本契约 → 单因子主链与评价 → 多因子合成及策略配置 → 页面/回测/模拟目标贯通 → 真实 A/B 与回归验收 → 日常任务和 SG 部署验收。部署时只纳入本次文件，核查当前仓库已有其他工作，避免将并行进行的 EP 等改动混入发布。

最终完成标准是：用户能在正常研究/策略流程中选择并保存行业处理方式，系统实际用对应因子版本完成单因子评价、多因子合成、策略回测和新模拟目标计算；每日分类归档与后续更新可运行，历史结果可复现，页面能解释分数与来源。仅有一份测试报告或一个独立对照脚本不满足完成标准。

交付还包括真实单因子和多因子 A/B 报告、逐日覆盖诊断、行业集中度变化、归档凭据和部署核验。功能正确与收益提升分别验收：中性化未提高某个因子收益并不表示功能失败，也不能据此隐去结果；是否将某个已有策略改用新方案由完整研究证据决定。若真实数据存在独立阻断，明确区分已完成能力与未完成研究，不能只凭单元测试通过宣称主流程和研究全部完成。
