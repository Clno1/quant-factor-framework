# EP 漏报修复与分阶段验收

## 本轮边界

本轮修改本地代码，没有部署 SG、修改 timer、触发付费 LLM 或发送 Discord。
只读导出了 SG 上三个失败案例的公开来源留档，用于离线回归。
仓库原有并行修改未回滚。本轮没有提交或推送 main。

这不是“完整 EP 雷达已上线”的验收结论：代码路径可用、数据输入可用和生产及时发现，是三个不同层次。

## 第一项：三个确定缺陷

| 案例 | 修复 | 已验证的范围 |
| --- | --- | --- |
| ORCL | SEC 搜索包含前一交易日，覆盖隔夜及节假日；仍拒绝观察时点之后的申报 | SG 原始 submissions JSON 能选出 `0001193125-26-387905`；不是完整 ORCL 正文到消息的成功验收 |
| CPRT | 同一 accession 内已分别匹配的主新闻稿和演示材料不再整体当作歧义 | 原始字节重放后主稿 `DOCUMENT_MATCHED`，支持材料独立留档；同日财报没有误并入并购 |
| RH | 清理不可见字符、定位实际标题；用发行人链和明确季度/财年补充标题关联 | 两份原始附件重放后主稿匹配，股东信作为支持材料保留；错误季度和并购标题仍拒绝 |

同一 accession 下多个不明主稿仍要求核查，不能任取第一份。支持材料保留不等于财务事实已批准，也不会每份附件重复调用模型。

时效校验允许有 SEC 接收时间佐证的隔夜后续报道，但不把该时间冒充公告最早发布时间，不把旧公告重新变成新催化。

源码：`src/breakouts/ep/discovery.py`、`sec_source.py`、`source_verifier.py`、`catalyst.py`。
真实回归：`tests/test_ep_peer_regressions.py`。
压缩字节及原始 SHA-256：`tests/fixtures/ep_peer_sources_20260911.json`。

## 第二项：事件队列与行情 WATCH

数据流：新闻原始记录 → 身份任务 → 事件分组 → 来源任务 → 原文版本分析 → 独立 outbox。

- 季度和财年明确的财报，以发行人、观察交易日、季度、财年分组，保留各篇新闻作为成员。
- 期间未知或并购、合同等未取得交易身份的事件，只合并同交易日同发行人的完全一致标题，不凭猜测合并不同标的或合同。
- 财报与并购不共用一个事件任务。跨发行人的买方/被收购方统一交易图尚未实现。
- 原始新闻任务不会删除。旧的待处理来源任务可转为事件任务，状态明确标为“已分组，不代表来源成功”。
- 来源失败后轮换成员标题尝试，避免一个不匹配的新闻标题永远卡住该事件。
- 已完成事件出现同一文章的新版本会重新核查来源；抓取期间出现修订也不会被完成状态吞掉。
- 预留重试和普通新闻容量；有新鲜价格 WATCH 的股票优先。不增加既有 LLM 额度。

队列数据库由 v1 增量升级到 v2，新增 `events`、`event_members`、`watch_history`；只读 v1 仍兼容。
首次生产运行前须备份 SQLite，不能用旧二进制读写升级后的数据库。

`watch.py` 是独立的价格观察路径，不修改杯柄和现有量能确认规则。
已验证股票/ADR、当前价格时间、前收盘交易日与复权口径合格时，默认涨幅 4% 可进入 `EP_WATCH`。
这个 4% 是可解释的宽观察阈值，不是成熟 EP 标准、买入条件或对截图拟合的收益结论。
未知催化允许 WATCH；未知量能显示 UNKNOWN，并丢弃未经验证的成交量/量比数值。ETF 不进入这条路径。

输入配置为可选的 `watch_input_path`，格式 `ep-price-watch-v1`，包含 `PriceObservation` 记录列表。
每条价格最多允许 120 秒陈旧；优先级同样会过期。它目前消费经过明确契约确认的输入，**不是已经接好了全市场 FMP 盘前自动扫描**。
不要为绕过数据缺口直接把 `price_contract_verified`、`adjustment_verified` 或 `volume_status` 改成已验证。

价格快照独立存档；状态、催化状态、量能状态变化，或相对上次重要更新的 gap 变化 2 个百分点、RVOL 变化 2 倍，产生增量变化记录。
记录价格回落、重复、过时输入，不因没有新闻而删除观察。WATCH 目前不自动发送 Discord。

离线导入入口：

```bash
python scripts/run_ep_event_worker.py --config /absolute/worker.json watch-input /absolute/watch.json
```

## 第三项：财务比较、更新与时效

新增可选 `financial_input_path`，格式 `ep-financial-input-manifest-v1`。
每个来源记录使用 `ep-bound-financial-observations-v1`，绑定 `source_id`、正文版本、输入契约、证据 ID、发布时点、完整财务观察对象和配对关系。
这是受信上游的标准化数据输入，不是允许 LLM 自填“已核准”标志的接口，也不是新的通用财报提取器。

程序检查主体、期间、币种、GAAP/非 GAAP、每股口径、单位、数值类型和时间：

- 实际值只能与公告前已留存、当时已发布的一致预期计算 SURPRISE。
- 本次公司指引与先前公司指引可计算 GUIDANCE_REVISION；不把它变成已实现业绩。
- 上年实际值不能冒充一致预期；缺少期间、币种或口径就阻断。
- 非正基数只给绝对差额，不给误导性的百分比。
- 输出分为原文摘录、独立程序比较、AI 解释；模型历史请求及预算台账不重写。
- 新的合格比较输入可为已分析事件产生新的投递版本，不再调用模型；仍遵循原有 Discord 冷却、通道核验和不确定投递处理。

**未完成的数据工作：**生产没有可靠历史一致预期输入，也没有已确认的盘前累计量/同刻量比输入。本轮没有伪造或用今天的预期补昨天的基准。
真实样本中的比较仍可能为空；不应因此声称“所有财务分析都恢复了”。

`explain --as-of` 从状态迁移表重建当时的队列状态，不使用后来的成功结果冒充历史成功，不混入当前 Discord 状态。

```bash
python scripts/run_ep_event_worker.py --config /absolute/worker.json explain ORCL --as-of 2026-09-11T12:15:00+00:00
```

源码：`event_identity.py`、`queue.py`、`pipeline.py`、`watch.py`、`financial_context.py`；
接入：`event_ingest.py`、`event_worker.py`、`src/alerts/ep_event.py`、`scripts/run_ep_event_worker.py`。

## 验收与下一道闸门

本地完整 EP 与突破隔离测试：546 passed，无跳过。使用应用已有 pypdf 包补齐临时测试路径，没有修改系统 Python。
测试包括真实公开原文字节、29 篇财报报道合为一个来源任务的合成压力场景、财报/并购分离、队列恢复、并发修订、未知催化 WATCH、未来/陈旧行情拒绝、涨幅回落、财务口径不匹配和不重复调用模型。
“29 篇”是测试场景，不是本轮对真实全队列压缩率的统计。

下一步必须在 SG 独立验收目录重放真实队列、检查资源与时限，再切生产。仍需完成：

1. ORCL 全部原文链路及三个案例到最终报告的端到端验收，避免把修复第一道过滤器当成已发送。
2. 可靠价格输入的生产适配，含全市场覆盖、观察时点、前收盘与复权；UNKNOWN 量能不能升级为已确认。
3. 历史预期/旧指引的可比数据绑定，补充材料财务正文利用，以及跨发行人的并购角色关联。
4. WATCH 增量消息的独立投递验收、真实队列发现延迟统计及 SG 部署回滚方案。

因此本轮是“修复确定漏报 + 接通可测试机制”，不是“完整复刻对方且已生产上线”。
