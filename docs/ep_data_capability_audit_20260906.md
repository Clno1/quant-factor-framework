# EP 数据能力验证报告

验证日期：2026-09-06。范围：现有 FMP 账户的只读接口验证、公开原始资料访问和截图案例数据覆盖。

配套阅读：[案例对照表](ep_case_acceptance_matrix_20260906.md)、[第一版范围与验收标准](ep_v1_scope_acceptance_20260906.md)。

## 1. 本次结论

**现有账户足以启动事件发现和基础财报分析，但尚不足以验收带有真实盘前量比的完整 EP 雷达。主要缺口是数据口径和历史证据，不是 AI API 权限。**

- 截图中的 17 个正式告警，都查到了发布时间早于截图截止时刻的相关催化公告线索。这里是已知名单检索，不是全市场扫描召回率。
- 15 个财报类案例都有实际值和预期值记录；NYAX、AVAV 是并购/合同，不应要求财报记录。
- 17 个案例都取得事件日常规时段分钟线；测试的这些分钟响应没有盘前、盘后 bar。**没有提供数据，不等于对应时段没有成交。**
- 扩展时段最近成交价与买卖报价有权限；盘前累计股数、累计成交额、同一时刻盘前量比仍未验证成立。
- 新闻和公告接口可用，但返回文本大多是短摘要。长篇电话会文本有可用样本；公司原文直连成功率、解析质量、可用时间仍需完善。
- 历史请求发现截断；分钟成交量与日线成交量存在显著差异；早盘缺分钟记录会影响 OR1/OR5。这些都必须进入数据契约。

## 2. 验证方法与边界

请求使用现有环境中的 FMP 密钥，以 `apikey` 请求头发送，没有将密钥写入 URL、报告或证据。探测只读取数据，将脱敏响应保存在 `reviews/2026-09-06-ep-data-capability/`，没有修改生产策略、数据发布版本、服务器服务或 Discord 配置。

本次在本地网络环境执行，日期为周日。验证了权限、响应内容、历史抽样和本地请求耗时；**没有验证 SG 网络、正常盘前更新延迟、供应商历史首次提供时间、全市场发现能力或策略收益。**

截图时间暂按 Asia/Shanghai 转换到 America/New_York；FMP 新闻和分钟 `date` 字段没有时区偏移，按项目既有交易所本地时间语义解释。正式接入必须用公告原始时间、交易所日历交叉校验。批量 quote 的时间戳为秒，扩展时段接口样本为毫秒，不能共用未经单位检查的转换。

截至本轮，FMP 留档请求共 109 次，另有 1 次未留档的初始连通性请求；不是压测。完整请求参数、字段、空值数、接收时间、耗时和结果见[机器汇总](../reviews/2026-09-06-ep-data-capability/case_evidence.json)。公开网站探测另计。网络权限受限时的首次 DNS 失败，不算 FMP 权限失败。

## 3. 数据能力清单

| 能力 | 账户实测 | 能支持什么 | 限制 / 接入要求 |
|---|---|---|---|

| `/batch-aftermarket-trade` | 17/17 返回价格和时间 | 扩展时段最近成交价 | `tradeSize` 16/17 为空；它本来也不是累计成交量 |
| `/batch-aftermarket-quote` | 17/17 返回 bid/ask、size、volume、时间 | 报价与价差质量分析 | volume 的累计范围、重置时间和交易所覆盖未确认；size 是盘口数量 |
| `/historical-price-eod/full` | 17/17 返回事件日前后日线 | 前收盘、开盘、日线参考值 | 日线开盘跳空不能代替 08:13 盘前跳空 |
| `/historical-chart/1min` | 17/17 有常规时段记录 | 盘中价格、候选开盘后观察的基础数据 | 无扩展时段；部分开盘分钟缺失；量能口径需核对 |
| `/historical-chart/5min` | SNOW 9/3 返回 78 根 | 5 分钟接口权限及形状验证 | 无扩展时段；没有据此证明与 1min 聚合完全一致 |
| `/earnings-calendar` | 有实际 EPS、EPS 预期、营收实际/预期 | 财报事件列表与初步 surprise 计算 | 大区间截断；无精确发布时间和 EPS 口径标签；需按日拉取 |
| `/earnings` | GTLB 返回 20 条 | 单公司历史/未来财报事件 | 历史 `lastUpdated` 为本次日期；不是事前快照 |
| `/analyst-estimates` | GTLB 季度数据 20 条 | 营收/EPS 等预测区间、分析师数量 | `date` 是预测对应期，不是预测发布时间；没有历史修订时序 |
| `/news/stock-latest`、`/news/stock` | 全局样本与 17 个案例都返回 | 新闻发现、历史线索查找 | 需分页和保存 first_seen；标题/摘要不能自动确认催化 |
| `/news/press-releases-latest`、`/news/press-releases` | 全局样本与 17 个案例都返回 | 公告发现及原文 URL | 混入律所招揽、合作方和其他主体公告；并非全是发行人公告 |
| `/earning-call-transcript` | GTLB FY2027 Q2 返回 51,593 字符 | 长篇业务指标、管理层说明提取 | 只验了一个样本；date 只有日期，无法证明盘前何时可得 |
| `/income-statement`、`/cash-flow-statement` | GTLB、AFRM 样本成功 | GAAP 财务比较和现金流背景 | 不能自动等同于财报事件的 adjusted EPS |
| `/profile` | NTSK、PSNYW 成功 | CIK、上市时间、证券身份辅助 | PSNYW 的公司名未写 warrant；不能只看非 ETF/非基金标志 |
| `/exchange-market-hours` | 成功，市场关闭 | 当前交易状态辅助 | 仍需交易所日历处理节假日、半日市和夏令时 |

## 4. 决定实现方式的实测发现

### 4.1 盘前累计量暂不能从已测数据可靠得到

17 个事件日的分钟记录都位于 09:30-15:59，盘前记录数为零。SNOW、VEEV、NYAX 的长历史抽样和更早单日抽样也没有返回扩展时段。

扩展报价虽然有 `volume`，但周五收盘后的样本大多接近日常 quote 的整日成交量。例如 SNOW 为 8,448,875.00527，对应普通 quote 为 8,431,642；NYAX 为 7,967.08421，对应 7,534。这提示它可能包含更大范围的累计量，但本次不能证明具体口径。

因此不能把这个字段直接命名为 `premarket_volume`，也不能把少数最近成交的 `tradeSize` 相加冒充累计量。间歇快照会漏掉两次请求之间的大量成交。

后续须确认字段的交易所范围、盘前/盘后时间边界、累计重置、是否包含开收盘竞价、是否复权及修订规则。若 FMP 当前产品不能提供所需历史和实时语义，再评估其他支持扩展时段的数据源。

拟定同钟盘前量比为 `今日 04:00 至 t 的累计成交量 / 过去 20 个有效交易日同一窗口成交量中位数`。分子、分母必须来自同一统计口径；历史不足、分母为零、漏数和当天采集中断须分别标记。它是拟定指标，不是已经实现或已验证等同截图的公式。

### 4.2 长区间请求成功，但没有返回整个区间

- 财报日历请求 8/24-9/10，返回恰好 4,000 行，最早仅到 8/27。随后按 8/24-9/3 的 9 个交易日分别请求，获得 5,605 行，且每次返回日期与请求日期一致。按日分片找回了 PLAB、ANF、OKTA、CRWD、VEEV 等记录。
- 1min 请求 7/27-9/3，SNOW 只返回 9/1-9/3 的 1,170 条，VEEV 1,163 条、NYAX 320 条，也只覆盖最后三个交易日。
- 单独请求 SNOW 7/27、VEEV 8/6、NYAX 8/20，都有历史数据。问题不能简单归为“账户只有三天历史”。

接入要求：分日或经证实的小窗口拉取；逐个核对期望 session；返回数量达到上限时继续分页/细分；零行与完整无事件不能直接画等号。历史长区间缺数必须显式暴露。

### 4.3 有完整分钟时间标签，不等于成交量可与日线直接混算

| 案例 | 常规 1min 数量 | 1min 成交量合计 | 日线成交量 | 两者比值 |
|---|---:|---:|---:|---:|
| ANF 8/26 | 390 | 1,777,348 | 17,242,400 | 10.31% |
| VEEV 8/27 | 390 | 2,711,258.43009 | 6,410,127 | 42.30% |
| NYAX 8/25 | 148 | 18,092.30883 | 68,311 | 26.49% |
| GTLB 9/2 | 388 | 20,313,072.38812 | 28,993,600 | 70.06% |

17 个案例的比值约为 10.31%-87.85%。**这不是已确认的行情覆盖率或丢包率。** 日线可能覆盖不同交易时段、竞价、成交条件、交易所或修订范围，原因尚未查明。本次既不能认定日线错，也不能认定分钟错，更不能用比例强行放大分钟成交量。

在口径确认前，不应把分钟累计量与日均量直接相除后声称“全市场真实 RVOL”。同源、同窗口的历史分钟基线也需验证覆盖是否稳定，不能仅凭“来自同一个 API”通过验收。现有日线/分钟量混合指标需要另行专项审计，本轮没有改动其逻辑。

### 4.4 开盘关键分钟存在缺口

- GTLB 9/2 缺 09:30、09:31，第一根为 09:32。不能据此构造真实 OR1，OR5 也缺证据。
- AGX 9/3 缺 09:31。OR5 必须标记不完整。
- NYAX 8/25 有 148 根 1min，只有 5 个包含五条源记录的完整 5min 桶。零成交、停牌、源漏数尚未分类。

缺失不能统一补零量、前向填充价格后当作真实成交。完整桶计数是数据结构检查，不等于满足柄或开盘突破规则。

### 4.5 财报字段够计算基础差值，口径和时点仍欠缺

GTLB 财报事件返回 EPS 0.24 / 预期 0.1798；收入表同期 GAAP EPS 为 -0.22。ANF 事件 EPS 为 4.17，AFRM 为 4.62，原始公告中的退款/税务影响不会自动被接口剔除。NTSK 的实际与预期均为负数，需使用绝对预期作分母或直接展示差值，避免符号颠倒。

这些案例的 `lastUpdated` 都是 2026-09-06。当前数据能做事后核对，不能证明 8/26 或 9/2 当时返回的预期就是今天这个值。正式留存至少要区分：财政期间、公告发布时间、供应商字段时间、本系统 first_seen、抓取时间、内容版本、EPS 基本/稀释及 GAAP/调整后口径。

公司“上调指引”需要同一期间的新旧公告；“超过市场预期”还要事前 consensus。两者不能互相代替。

### 4.6 公告摘要不是全文，原文访问不能只依靠一个网站

17 个主催化公告的 FMP 文本约 200-978 字符，GTLB 只有 500 字符。足以发现事件，但不足以稳定提取完整 ARR、NRR、税项、并购条款与风险。

GTLB 电话会接口返回 51,593 字符；本次证据只保存长度、哈希和短节选，没有复制整篇长文。财政年参数使用 2027，事件发生年为 2026；需要处理财政年与自然年映射。

| 公开源直连抽样 | 结果 | 意义 |
|---|---|---|
| SEC submissions JSON | HTTP 200 | 可取 accession、表单与 acceptanceDateTime |
| SEC companyfacts JSON | HTTP 200 | 可取标准 XBRL；本样本无 ARR/留存率等匹配字段 |
| SEC Archives 8-K 附件目录 | HTTP 403 | 本次自动请求被限制，未绕过；需按公开访问规范解决接入 |
| GitLab IR 公告 | HTTP 429 / challenge | 不能假定公司官网稳定可抓 |
| GlobeNewswire / NYAX | 读取超时 | 一个请求样本，不代表永久不可用 |
| Business Wire / DELL | 读取超时 | 同上 |
| PRNewswire / VEEV | HTTP 200，HTML 含核对数字 | 证明一条原文路径可访问；尚未验收完整正文解析 |

公开源元数据见 `evidence/sec_*.json`、`evidence/*release*.json`。SEC 标准 JSON API 的范围见[官方说明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)。SG 的网络、声明式 User-Agent 和限流配置需在部署前独立验证。

### 4.7 催化筛选必须处理主体、重复和噪声

PLAB 的公告接口返回 33 条记录，多数为律所诉讼招揽提醒；真正财报在 8/26 07:00。DELL 同一财报以末尾斜杠不同的 URL 出现两次。SNOW 公告列表还包含合作方内容。`press-releases` 不是“已验证的发行人重要事件”列表。

需要事件聚类、发行人/合作方/律所角色识别、原始事件时间、内容去重和风险标签。找不到新闻只能标记“当前抓取范围内未找到证据”，尤其在列表达到 limit 时，不能断言“没有催化”。NVDA 的两页各有 100 条、URL 无重叠，但最早仍仅到 8/26 16:45:40，尚未覆盖更早的财报发布时刻。本轮没有继续穷尽该窗口，不将“未查到原始财报”解释为无催化。

## 5. 对第一版的决定

可以先开发：独立事件候选入口、按日财报日历、新闻和公告增量收集、公司身份解析、基础实际值/预期对照、证据留存、观察状态和离线报告。

需要补齐才能正式宣称：盘前累计量、同钟 RVOL、Strong 的流动性确认、与截图一致的分钟级触发时刻、历史无未来信息回放。AI 只能处理取得的资料，不能修补这些缺失数据。
