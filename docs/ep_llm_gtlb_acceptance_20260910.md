## 已证实与未证实

1. `/v1/models` 鉴权成功且模型可见；实际生成也已返回 `kimi-k2.6`。不需要重新提供密钥。
2. 官方 `/v1/users/me/balance` 只读查询 HTTP 200，可用余额约人民币 64.85 元。
   这排除了检查当时的余额耗尽，但不能代替对 429 的并发、RPM、TPM、TPD 或节点过载的逐项判断。
3. 成功响应等了约 77.95 秒才取得 headers。原 60 秒配置不足以等待这次同 payload 的响应；
   这支持原首次超时的嫌疑，不能倒推出原首次必然是同一种原因。
4. 原始归档响应确切报告 `prompt_tokens=11205`、`completion_tokens=4000`、
   `cached_tokens=10240`。正文共 12,397 字符，末尾停在 EPS 事实的引用中间，没有闭合 JSON。
5. `LLM_RESPONSE_INCOMPLETE` 是正确的拒绝行为，不是解析器应该容错补全的情况。
   HTTP 成功、JSON 完整、引用校验通过、财务语义正确是四个不同验收层级。

## 官方文档核对

- [K2.6 参数](https://platform.kimi.com/docs/guide/kimi-k2-6-quickstart)：国内 base URL 为
  `https://api.moonshot.cn/v1`；允许 `thinking.type=disabled`，`n=1`。当前配置匹配。
- [Chat 参数](https://platform.kimi.ai/docs/api/chat)：支持 `max_completion_tokens`；
  达到上限时返回 `finish_reason=length`。当前不是因为参数名拼错而拒绝。
- [结构化输出](https://platform.kimi.ai/docs/guide/response_format)：支持 JSON Schema；
  K2.6 对复杂 schema 存在不稳定性，建议简化 schema 并在业务端二次校验。
  现有展开引用的 schema 和本地严格校验应保留。
- [错误说明](https://platform.kimi.com/docs/api/errors)：429 可能表示过载、速率或额度问题，
  不能一律解释为余额不足，也不能一律建议充值。
- [查询余额](https://platform.kimi.com/docs/api/balance)：余额查询是只读请求，不是推理。

文档中的自动重试示例不直接用于本试验。我们要求人工指定父请求、每次重新预留预算、保留失败，
且同一请求链最多两次网络类人工重试；没有接入 SDK 默认重试。
